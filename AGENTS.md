# shadcn-light-design — правила проекта

Единственный источник правил для работы в этом репозитории, для людей и для ИИ-агентов.
`CLAUDE.md` подключает этот файл. Правила для тех, кто **применяет** систему в своих
проектах, — в `DESIGN.md`.

## Что это

Универсальная **светлая** дизайн-система для проектов на shadcn/ui: Tailwind v4,
примитивы Base UI, стиль `base-nova`. Репозиторий — обычный shadcn-проект:
- тема — в `src/index.css`;
- все компоненты shadcn — в `src/components/ui/`;
- витрина — в `src/showcase/`.

Тёмная тема здесь не проектируется: блок `.dark` зарезервирован под отдельный продукт.

## Главный принцип: дизайн живёт в `src/index.css`

Компоненты shadcn копируются из реестра и **почти не меняются**. Любое визуальное решение
сначала пытаемся выразить в `index.css`, в таком порядке:

1. **Переменные.** Роли, радиусы, шрифты, тени.
2. **Шкалы Tailwind в `@theme`.** Например, какие значения стоят за `rounded-lg`, которым
   пользуется shadcn.
3. **Хуки `data-slot` в `@layer base`.** Например,
   `[data-slot$="-description"] { font-family: var(--font-text) }`.

Править класс в компоненте можно только в двух случаях:
- **Добавить вариант для роли, которой нет в shadcn:** `success`, `warning`, `info`.
- **Добавить рамку мягкому варианту**, у которого её нет: элемент не должен сливаться
  с поверхностью.

Каждое отклонение от оригинала записывается в `UPSTREAM.md`: файл, что изменено, почему.
Без записи правку не делаем. Это нужно, чтобы обновлять компоненты через
`shadcn add <имя> --dry-run` / `--diff` и не терять свои изменения.

## Устройство `src/index.css`

| Раздел | Что | Правило |
|---|---|---|
| 1. Палитра | шкалы `--neutral-*`, `--brand-*`, `--green-*`, `--red-*`, `--amber-*`, `--blue-*` | единственное место с конкретными цветами |
| 2. Роли | контракт shadcn (`--background`, `--primary`, `--border` …) + `--success`, `--warning`, `--info` с `-foreground` | каждая роль — `var(--<шкала>-<ступень>)`, без литералов |
| 3. Регистрация в Tailwind | `@theme` / `@theme inline` | стандартные палитра, радиусы и тени Tailwind отключены (`--color-*: initial` и т.п.) |
| 4. Типографика и утилиты | `type-*`, `focus-ring`, хуки `data-slot` | стили текста называются стандартно: display, h1–h4, ui-lg/ui/ui-sm, body, caption |

Новых переменных «под компонент» (`--button-bg`, `--order-book-bid`) не заводим.
Смысл предметной области (покупка → `success`, продажа → `destructive`) описывается
в `DESIGN.md`, а не токенами.

## Решения системы

- **Шрифты.**
  - Tektur (`font-heading`) — заголовки.
  - JetBrains Mono (`font-sans`, шрифт по умолчанию) — весь интерфейс, контролы, числа.
  - Inter (`font-text`) — только связный текст: описания, подсказки, сообщения, ошибки под полями.

  Шрифты ставятся пакетами `@fontsource-variable/*`, не с Google CDN.
- **Радиусы.** 2px — контролы, 4px — контейнеры. `rounded-full` — только точки статуса,
  радио и аватары.
- **Тени.** Только у слоёв над страницей: `shadow-md` у меню и тултипов, `shadow-lg` у
  диалогов и тостов. Карточки и контролы без теней, с рамкой.
- **Края.** У каждого элемента видимая граница на любой поверхности (`background`, `card`,
  `muted`): либо сплошная заливка, либо рамка. Мягкий вариант — заливка 10% + рамка 40%
  того же цвета.
- **Фокус.** Сплошной, без прозрачности, ≥3:1 к любой поверхности.

## Пороги контраста (WCAG)

| Пара | Порог |
|---|---|
| текст и `-foreground` на своей заливке, статус текстом на мягкой подложке | ≥ 4.5:1 |
| рамка контрола (`input`), фокус (`ring`), линии графиков | ≥ 3:1 |
| лёгкая рамка `border` к поверхности | ≥ 1.3:1 |
| край мягкого варианта (цвет /40) к поверхности | ≥ 1.5:1 |

Каждая пара проверяется на всех трёх поверхностях. Если значение не проходит — меняется
ступень палитры, а не порог.

## Запрещено

- Сырые цвета и произвольные значения в компонентах и витрине: `bg-red-500`, `text-[#333]`,
  `rounded-[6px]`, `shadow-xl`. Только роли и шкалы системы. Витрина может обращаться
  к палитре (`var(--brand-500)`), но только чтобы её показать.
- Включать обратно стандартную палитру, радиусы или тени Tailwind.
- Добавлять классы `dark:` — тёмная тема не наша задача.
- Прятать проблему контраста прозрачностью: `text-foreground/60` вместо
  `text-muted-foreground`.
- `shadcn add --overwrite` без явного согласия пользователя.

## Витрина (`src/showcase`)

- Значения не дублируются: шкалы и привязка ролей читаются из `index.css` (`?raw`), цвета и
  контраст — из браузера (`getComputedStyle` + canvas).
- Каждый компонент показывается во всех вариантах и состояниях на трёх поверхностях.
- Тексты витрины и документации — на русском.

## Работа с shadcn

- CLI запускается через `pnpm dlx shadcn@latest …`, скилл shadcn — источник правил композиции.
- Перед правкой или использованием компонента — `pnpm dlx shadcn@latest docs <имя>`
  и чтение примеров, API не угадываем.
- Обновление компонентов: `add <имя> --dry-run`, затем `--diff <файл>`; свои отличия берутся
  из `UPSTREAM.md`.
- Линтер: для `src/components/ui/**` и `src/hooks/**` отключены `only-export-components`
  и `set-state-in-effect` — это штатный код shadcn, под линтер его не переписываем.

## Проверка перед тем, как показывать результат

1. `pnpm lint` и `pnpm build` — без ошибок.
2. Тест контраста — зелёный (появится на этапе 2).
3. Скриншоты витрины просмотрены глазами: ничего не сливается с фоном, нет обрезанного текста,
   шрифты на своих местах.

## Зависимости и git

- Пакетный менеджер — pnpm. Новые пакеты — последней версии. Популярность и актуальность
  сверяются через `npm view`.
- Ветка `main`. Коммиты — Conventional Commits (`feat:`, `fix:`, `refactor:`, `docs:`,
  `chore:`), описание на русском.
