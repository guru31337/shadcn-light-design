# shadcn-light-design — правила проекта

Единственный источник правил для работы в этом репозитории, для людей и для ИИ-агентов.
`CLAUDE.md` подключает этот файл. Правила для тех, кто **применяет** систему в своих
проектах, — в `DESIGN.md`.

## Что это

Универсальная **светлая** дизайн-система для проектов на shadcn/ui: Tailwind v4, примитивы
Base UI, стиль `base-nova`. Репозиторий — обычный shadcn-проект и одновременно реестр shadcn:
- тема — `src/index.css`;
- компоненты — `src/components/ui/`;
- витрина — `src/showcase/`;
- реестр для установки из GitHub — `registry.json`.

Тёмная тема здесь не проектируется: блок `.dark` зарезервирован под отдельный продукт.

## Принцип №0: универсальность не меньше индивидуальности

В первую очередь сохраняем то, как всё построено в shadcn. Индивидуальность системы — это
**значения** (цвета, шрифты, радиус), а не другая **структура**. Тема должна подходить любому
shadcn-проекту: её можно открыть в tweakcn, обновить компоненты через CLI, а чужие блоки из
реестров должны работать без адаптации.

- **`index.css` повторяет то, что генерирует `shadcn init`.** Порядок: `@theme inline` →
  `:root` → `@layer base`. Имена переменных и маппинг `--color-*` — как у shadcn. Радиусы —
  одна переменная `--radius`, остальные shadcn считает от неё своей формулой
  (`calc(var(--radius) * 0.6)` … `* 2.6`).
- **Стандарты Tailwind не отключаем и не переопределяем:** палитру, тени, размеры текста,
  отступы.
- **Добавка — только там, где у shadcn нет решения.** Сейчас это роли `success`/`warning`/`info`,
  шрифт связного текста `--font-text`, шкала заголовков `type-*` и палитра как источник значений
  ролей. В `index.css` добавки помечены «+». Новая добавка требует обоснования: что именно shadcn
  не умеет.
- **Прежде чем что-то добавить, проверяем, нельзя ли обойтись значением существующей
  переменной.**

## Правило №1 (строгое): всё, что можно решить в `src/index.css`, решается там

Компоненты shadcn копируются из реестра и остаются **побайтово такими, как в реестре**.
shadcn уже развёл роли по переменным и именам шкал: `bg-primary`, `ring-ring`, `rounded-lg` —
у контролов, `rounded-xl` — у карточек, `data-slot` — у каждой части. Обычно достаточно один раз
задать значения в `index.css`.

Прежде чем трогать компонент, по порядку пробуем:

1. **Значение существующей переменной:** роли, `--radius`, шрифты.
2. **Правило по `data-slot` в `@layer base`.** Например,
   `[data-slot$="-description"] { font-family: var(--font-text) }`.

Компонент правится, **только если ни один способ не работает**. Допустимых случаев два:
- **Нужен вариант для роли, которой нет в shadcn:** `success`, `warning`, `info`. Новый вариант
  повторяет паттерн существующего `destructive`, без классов `dark:`.
- **У варианта нет края, и он сливается с поверхностью.** Добавляется только рамка.

Каждая правка компонента заранее записывается в `UPSTREAM.md`: файл, что изменено, почему это
нельзя решить в `index.css`. Без записи правку не делаем. Форматтер по `src/components/ui/`
не запускается: папка в `.prettierignore`, иначе классы пересортируются и `shadcn add --diff`
покажет шум.

## Устройство `src/index.css`

| Блок | Что | Правило |
|---|---|---|
| `@theme inline` | маппинг ролей в цвета Tailwind, шрифты, формула радиусов | как у shadcn; + `--color-success/warning/info`, `--font-text` |
| `:root` (роли) | контракт shadcn (`--background`, `--primary`, `--border` …) + `--success`, `--warning`, `--info`, `--radius` | роль = `var(--<шкала>-<ступень>)` |
| `:root` (палитра) | шкалы `--neutral-*`, `--brand-*`, `--green-*`, `--red-*`, `--amber-*`, `--blue-*` | единственное место с конкретными цветами; в реестр не уходит |
| `@utility type-*` | display, h1–h4, body, caption | интерфейсный текст — обычные `text-xs/sm/base` шрифтом по умолчанию |
| `@layer base` | как у shadcn + Inter для `data-slot` описаний и `p`, заголовки h1–h4 | — |

Новых переменных «под компонент» (`--button-bg`, `--order-book-bid`) не заводим. Смысл
предметной области (покупка → `success`, продажа → `destructive`) описывается в `DESIGN.md`,
а не токенами.

## Решения системы

- **Шрифты.**
  - Tektur (`--font-heading`) — заголовки.
  - JetBrains Mono (`--font-sans`, шрифт по умолчанию) — интерфейс, контролы, числа.
  - Inter (`--font-text`) — только связный текст: описания, подсказки, сообщения, ошибки под
    полями, `p`.

  Шрифты ставятся пакетами `@fontsource-variable/*`, как это делает сам shadcn для Vite.
- **Радиус.** `--radius` (сейчас `0.25rem` = 4px). Меню, кнопки, карточки, бейджи получают свои значения
  по формуле shadcn.
- **Тени.** Стандартные тени Tailwind в том виде, как их расставил shadcn: только у слоёв над
  страницей.
- **Края.** У каждого элемента видимая граница на любой поверхности (`background`, `card`,
  `muted`): либо сплошная заливка, либо рамка.
- **Фокус — штатный из shadcn:** рамка цвета `--ring` и ореол `ring/50`. Настраивается только
  `--ring`, сама рамка должна давать ≥3:1 к любой поверхности.

## Пороги контраста (WCAG)

| Пара | Порог |
|---|---|
| текст и `-foreground` на своей заливке, статус текстом на мягкой подложке | ≥ 4.5:1 |
| рамка контрола (`input`), фокус (`ring`), линии графиков | ≥ 3:1 |
| лёгкая рамка `border`, заливка без рамки (`secondary`) к поверхности | ≥ 1.3:1 |
| край мягкого варианта (цвет /40) к поверхности | ≥ 1.5:1 |

Каждая пара проверяется на всех трёх поверхностях. Если значение не проходит — меняется
ступень палитры, а не порог.

## Реестр и распространение

- **`registry.json` генерируется, руками не правится:** `pnpm registry`
  (`scripts/build-registry.mjs`) после любой правки `index.css` или изменённых компонентов.
  Затем `pnpm dlx shadcn@latest registry validate ./registry.json`.
- **Элементы реестра:**
  - `theme` — роли с подставленными значениями, без палитры;
  - шрифты `font-*`;
  - изменённые компоненты `button`, `badge`, `alert`;
  - `light-design` — всё вместе.

  Остальные компоненты потребитель ставит штатно из shadcn.
- **Установка в проект:** `pnpm dlx shadcn@latest add guru31337/shadcn-light-design/light-design`.
- **Песочница tweakcn.** Раздел витрины отдаёт роли в формате импорта tweakcn. Удачные значения
  из tweakcn переносятся в палитру, роли продолжают ссылаться на ступени.

## Запрещено

- Сырые цвета и произвольные значения в своём коде (витрина, паттерны, примеры):
  `bg-red-500`, `text-[#333]`, `rounded-[6px]`. Только роли и шкалы. Витрина может обращаться
  к палитре (`var(--brand-500)`), но только чтобы её показать.
- Менять структуру `index.css` относительно shadcn без записи обоснования (принцип №0).
- Добавлять классы `dark:` — тёмная тема не наша задача.
- Прятать проблему контраста прозрачностью: `text-foreground/60` вместо
  `text-muted-foreground`.
- `shadcn add --overwrite` без явного согласия пользователя.

## Витрина (`src/showcase`)

- Значения не дублируются: шкалы и привязка ролей читаются из `index.css` (`?raw`), цвета и
  контраст — из браузера (`getComputedStyle` + canvas).
- Страница на тему или компонент (`src/showcase/pages/`, реестр — `pages.ts`), навигация
  слева. Страница компонента разбита на секции: варианты, размеры, состояния, пример в контексте;
  у каждого образца подпись с его вариантом.
- Поверхность превью (страница / карточка / утопленный) переключается в шапке. Каждый компонент
  проверяется на всех трёх.
- Витрина собирается из компонентов системы (`Tabs`, `Table`, `Card` …) и ролей, без своих цветов.
- Тексты витрины и документации — на русском.

## Работа с shadcn

- CLI запускается через `pnpm dlx shadcn@latest …`, скилл shadcn — источник правил композиции.
- Перед правкой или использованием компонента — `pnpm dlx shadcn@latest docs <имя>` и чтение
  примеров, API не угадываем.
- Обновление компонентов: `add <имя> --dry-run`, затем `--diff <файл>`; свои отличия берутся
  из `UPSTREAM.md`.
- Сайт shadcn ограничивает частоту запросов (отвечает 403). Много запросов подряд не делаем:
  без нужды не ставим всё через `add --all` и не запрашиваем документацию пачками.
- Линтер: для `src/components/ui/**` и `src/hooks/**` отключены `only-export-components`
  и `set-state-in-effect` — это штатный код shadcn, под линтер его не переписываем.

## Проверка перед тем, как показывать результат

1. `pnpm lint` и `pnpm build` — без ошибок.
2. `pnpm registry` и `registry validate` — если менялись тема или компоненты.
3. Тест контраста — зелёный (появится на этапе 2).
4. Скриншоты витрины просмотрены глазами: ничего не сливается с фоном, нет обрезанного текста,
   шрифты на своих местах.

## Зависимости и git

- Пакетный менеджер — pnpm. Новые пакеты — последней версии. Популярность и актуальность
  сверяются через `npm view`.
- Ветка `main`. Коммиты — Conventional Commits (`feat:`, `fix:`, `refactor:`, `docs:`,
  `chore:`), описание на русском.
